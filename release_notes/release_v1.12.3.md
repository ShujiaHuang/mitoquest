# mitoquest v1.12.3 — caller: add `--output-ref-sites`

## Highlights

This **patch release** adds an opt-in switch, `--output-ref-sites`, to
`mitoquest caller`. By default nothing changes: the VCF contains variant sites
only, exactly as in v1.12.2. When the switch is given, the sites that
mitoquest judges to be **REF-only** (non-variant) are also written out.

### What a REF-only record looks like

| Field | Value |
|---|---|
| `ALT` | `.` |
| `QUAL` | `.` |
| `FILTER` | `REF_ONLY` |
| `INFO` | `PT=Ref`; `VAF_MEAN` and `VAF_MEAN_HET` are `.` |
| `FORMAT` / samples | the usual per-sample fields (GT `0`, DP, AD, AF, ...) |

Because `FILTER` is `REF_ONLY` for these records and `.` for variant records,
they are easy to select or drop with bcftools:

```bash
bcftools view -f REF_ONLY out.vcf.gz   # REF-only sites
bcftools view -f .        out.vcf.gz   # variant sites only
```

### Important: coverage scope

Only sites covered by **at least one read (passing `-Q` / `-q`) in at least one
sample** are written. The output is **not** a record for every position of the
mtDNA. A position that is absent from the VCF is *uncovered*; it does **not**
mean the position is REF. This is stated in `mitoquest caller -h` and in the
README.

## What changed

- `src/mt_variant_caller.{h,cpp}`: new `Config::output_ref_sites` and the
  `--output-ref-sites` long option (default off); REF-only sites are no longer
  discarded in `_joint_variant_in_pos` when the switch is on, `FILTER` is set to
  `REF_ONLY`, and a REF-only site with no non-missing genotype is skipped rather
  than raising an exception. `INFO` `VAF_MEAN` / `VAF_MEAN_HET` are written as
  `.` (instead of an empty value) when a record has no ALT allele.
- `src/mt_utils.{h,cpp}`: `VCFRecord::is_valid(bool allow_ref_only = false)`
  (default behaviour unchanged); the VCF header now defines
  `##FILTER=<ID=REF_ONLY,...>`.
- `tests/test_mt_variant_caller.cpp`: new test
  `MtVariantCaller.OutputRefSitesEmitsCoveredRefOnlySitesWithRefOnlyFilter`.
- `README.md`, `UPDATELOG.md`: parameter reference and changelog.
- `CMakeLists.txt`: `project(MITOQUEST VERSION 1.12.2 → 1.12.3)`
  (`src/version.h` is generated by CMake, not hand-edited).

## Compatibility

- Without `--output-ref-sites` the records are unchanged. The only difference
  in the VCF is one additional `##FILTER=<ID=REF_ONLY,...>` header line.
- With the switch on, the VCF is larger: roughly one extra line per covered
  non-variant site, each carrying all sample columns.
- Downstream tools that assume every record has an ALT allele should filter
  `FILTER=REF_ONLY` records first.
