# mitoquest v1.12.2 — ne-estimate: rename the primary estimator MMLE → MCMLE

## Highlights

This **patch release** corrects the *name* of the default `ne-estimate`
estimator. The estimator itself is **numerically unchanged** — every reported
`Ne`, confidence interval, and log-likelihood value is identical to v1.12.1
(verified: the emitted `Max_Composite_Marginal_LogLik` equals the old
`Max_Marginal_LogLik` byte-for-byte on the same input).

The label **MMLE ("Maximum Marginal Likelihood Estimator")** was imprecise.
The objective maximised by `ne-estimate` is the *sum* of per-pair marginal
log-likelihoods,

\[
\ell(N_e) = \sum_i \ell_i(N_e),
\]

where each \(\ell_i\) is the marginal likelihood of one mother→child
transmission pair after the latent child frequency \(p_C\) is integrated out
(analytically, under the Beta-diffusion / Beta-Binomial model). The pairs are
then treated as independent and their marginal log-likelihoods added and
maximised. Building a likelihood from independent blocks of a dependent model —
i.e. summing lower-dimensional (marginal) likelihoods as if independent — is
the textbook **composite (pseudo-) likelihood** construction (Varin, Reid &
Firth 2011). The statistically accurate name is therefore **MCMLE — Maximum
Composite Marginal Likelihood Estimator**. The JSON `Estimator` string had
already half-acknowledged this ("MMLE (composite marginal likelihood)"); this
release makes the name consistent end-to-end.

Following the project's convention for terminology corrections, the version is
a **patch increment** `1.12.1 → 1.12.2`. Note this rename also touches the
**machine-readable output schema**, which is a breaking change for downstream
parsers (see *Migration* below) — the same class of change that shipped as a
patch at v1.8.6 (MLE → MMLE).

## Breaking: output schema renames (for downstream parsers)

The estimator relabel renames user-visible columns, JSON keys, and profile
header fields. **Values are unchanged; only the names move.**

| Surface | Old (≤ v1.12.1) | New (v1.12.2) |
|---|---|---|
| Per-family TSV column | `NE_MMLE` | `NE_MCMLE` |
| Top-level JSON key | `Max_Marginal_LogLik` | `Max_Composite_Marginal_LogLik` |
| JSON `Estimator` value | `"MMLE (composite marginal likelihood)"` | `"MCMLE (composite marginal likelihood)"` |
| `--ne-profile` TSV columns | `mmle_log_lik`, `mmle_delta_2ll` | `mcmle_log_lik`, `mcmle_delta_2ll` |
| `--ne-profile` header meta | `#fitted_ne_mmle`, `#fitted_ne_mmle_ci_low`, `#fitted_ne_mmle_ci_high`, `#best_ne_mmle_on_grid` | `#fitted_ne_mcmle`, `#fitted_ne_mcmle_ci_low`, `#fitted_ne_mcmle_ci_high`, `#best_ne_mcmle_on_grid` |

Intentionally **unchanged** (these names are already accurate and are *not*
part of the estimator label):

- The profile meta key `#max_marginal_log_lik` (a per-pair marginal quantity,
  correctly named).
- `marginal_likelihood` symbols in `src/algorithm.cpp` / `src/basetype.cpp`
  (unrelated EM routines).

### Migration

- If you parse the JSON, read `Max_Composite_Marginal_LogLik`; if you need to
  support both versions, fall back:
  `obj.get("Max_Composite_Marginal_LogLik", obj.get("Max_Marginal_LogLik"))`.
- If you parse the per-family TSV by header name, look for `NE_MCMLE`.
- The bundled Python tools already handle this: `tools/plot_ne_profile.py` and
  the `ne-estimate` validation scripts read the new `mcmle_*` /
  `Max_Composite_Marginal_LogLik` names first and **automatically fall back** to
  the legacy `mmle_*` / `Max_Marginal_LogLik` (and the older `mle_*` /
  `Max_LogLik`) generations, so checked-in sample profiles from any prior
  version keep rendering.

## What changed

- `src/ne_estimate.{h,cpp}`, `src/main.cpp`: CLI help, JSON keys, per-family TSV
  header, profile columns and header meta, and all internal identifiers /
  comments relabelled MMLE → MCMLE (Maximum Composite Marginal Likelihood
  Estimator). No behavioural change.
- `tests/test_ne_estimate.cpp`, `tests/test_trio_likelihood_mpmath.py`:
  assertions and JSON-key reads updated to the new schema (mpmath cross-check
  reads the new key with a legacy fallback).
- `tools/plot_ne_profile.py`, `tools/plot_bottleneck_simulation.py`,
  `tools/plot_mito_bottlenechk_smulation.py`,
  `tests/data/ne_pipeline/{validate_estimators.py,synthesize.py,ne_diagnostic.py}`:
  plot labels relabelled to MCMLE; profile/JSON data keys updated to read the
  new names with multi-generation backward-compatible fallbacks.
- `README.md`, `tools/README.md`: prose, output-schema examples, and the LaTeX
  `\text{MCMLE}` math label updated.
- `CMakeLists.txt`: `project(MITOQUEST VERSION 1.12.1 → 1.12.2)`
  (`src/version.h` is generated by CMake `configure_file`, not hand-edited).

## Validation

- **Numerically identical**: on `BIGCS_II.M_C` the estimator produces the same
  fitted `Ne` and the same log-likelihood value as v1.12.1 — only the key name
  moved (`-12164.025`, matching the pre-rename golden fixture exactly).
- **Build + tests** (macOS / arm64, Apple clang): clean compile; GoogleTest
  **189/189**; `ctest` **3/3** — including `TrioLikelihoodMpmathCrossCheck`
  reading the new `Max_Composite_Marginal_LogLik` key, and
  `NeEstimateJsonSerialization`.
- **Runtime schema smoke test**: fresh `ne-estimate` output emits
  `"Estimator": "MCMLE (composite marginal likelihood)"`, the
  `Max_Composite_Marginal_LogLik` key, and `mcmle_*` profile columns /
  `#fitted_ne_mcmle*` header meta.
- **Backward compatibility**: `tools/plot_ne_profile.py` renders both a new
  `mcmle_*` profile and a legacy `mmle_*` fixture (three-level fallback proven).
- **Rename completeness**: repository-wide grep confirms zero MMLE/mmle residue
  in delivered source, tests, tools, and active docs, except (a) intentional
  Python fallback literals, (b) untracked golden fixtures, and (c) real
  filename references.
